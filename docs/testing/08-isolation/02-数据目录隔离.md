## [P1] release 使用 MIR3 独立数据目录

[测试类型] 功能

[前置条件] release 构建首次启动；未设置 `MIR3_STUDIO_HOME`

[测试步骤] 启动应用并查看运行时信息中的 `data_dir` 与 Tauri AppData。

[预期结果] `data_dir` 为 `~/.mir3-studio-ai`；AppData identifier 为 `ai.mir3.studio`；store 文件为 `.store.dat`。

## [P1] debug 与 release 数据隔离

[测试类型] 功能

[前置条件] release 监听 3080；debug 构建可运行。

[测试步骤] 同时运行两种构建，分别创建档案并重启核心服务。

[预期结果] debug 使用 `~/.mir3-studio-ai.dev`、`.store.dev.dat` 与 3081；release 使用 `~/.mir3-studio-ai`、`.store.dat` 与 3080；两侧档案、会话和进程互不影响。

## [P1] 不访问其他产品数据

[测试类型] 安全性

[前置条件] 用户主目录和 AppData 中存在其他应用的任意测试目录与哨兵文件。

[测试步骤] 首次启动、安装依赖、启停核心并退出 MIR3 Studio AI；监控文件访问并核对哨兵。

[预期结果] 应用只访问 `ai.mir3.studio`、`~/.mir3-studio-ai` 或显式 `MIR3_STUDIO_HOME`；其他目录未被读取、移动、改写或删除。

## [P2] 数据覆盖变量

[测试类型] 功能

[前置条件] 将 `MIR3_STUDIO_HOME` 指向一个新的临时目录。

[测试步骤] 启动应用并创建档案。

[预期结果] 运行时信息和实际写入均指向该临时目录；外部 `DSH_HOME` 不影响 MIR3 数据目录。
